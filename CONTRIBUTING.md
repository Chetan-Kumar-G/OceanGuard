# Contributing to OceanGuard

Thanks for taking the time to contribute! This document explains how to get
set up and what we expect from contributions.

## Code of Conduct

This project and everyone participating in it is governed by the
[Code of Conduct](CODE_OF_CONDUCT.md). By participating, you are expected to
uphold it. Please report unacceptable behavior to the maintainers.

## Getting Started

1. Fork the repository and clone your fork.
2. Create a branch for your change: `git checkout -b my-feature`.
3. Make your changes, including tests and documentation where relevant.
4. Ensure the test suite and linters pass.
5. Commit using clear, descriptive messages.
6. Push to your fork and open a pull request against `main`.

## Reporting Bugs

Open an issue and include:

- What you expected to happen and what actually happened
- Steps to reproduce
- Version, operating system, and any relevant configuration
- Logs or screenshots if available

For security issues, follow [SECURITY.md](SECURITY.md) instead of opening a
public issue.

## Suggesting Enhancements

Open an issue describing the problem you want solved, the proposed solution,
and any alternatives you considered.

## Pull Request Guidelines

- Keep pull requests focused; one logical change per PR.
- Update documentation and tests alongside code changes.
- Describe the motivation and the approach in the PR description.
- Link any related issues.
- Be responsive to review feedback.

## Commit Messages

- Use the imperative mood ("Add feature" not "Added feature").
- Keep the summary line under ~72 characters.
- Explain *why* in the body when it is not obvious.
